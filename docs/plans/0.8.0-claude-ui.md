# Plan 0.8.0 — Fournisseur Claude + refonte de l'interface

Statut : **plan, non implémenté**. Rédigé le 2026-11-13. Exécution prévue par des sous-agents (Sonnet 5.5).

## Décisions prises

| Sujet | Décision |
|---|---|
| Appel du modèle | **Claude Code CLI en mode headless** (`claude -p`), en sous-processus, comme pi. Utilise l'abonnement Claude existant, aucune clé API à gérer. |
| Modèle / effort par défaut | `claude-sonnet-5-5`, `--effort medium` (configurable par tâche). |
| pi | **Conservé en option** : `llm.provider: claude | pi`. Claude par défaut. |
| UI | **Refonte structurée en JS natif**, sans build (extension MV3). Découpage de `sidepanel.js`, nouvelle hiérarchie, tokens CSS + mode sombre. |

Invariants à ne jamais casser : ApplyPilot ne clique jamais sur « Soumettre » ; serveur sur 127.0.0.1 seulement ; aucun raisonnement interne stocké ni affiché ; la langue de l'interface ne change pas la langue des documents ; tout texte d'UI passe par `tr()` avec clé FR et traduction EN dans `extension/i18n.js`.

## Phase 1A — Fournisseur Claude (serveur) · agent « backend »

Fichiers possédés : `server/src/llm*.js`, `server/src/config.js`, `config.example.yaml`, `server/src/index.js` (seulement `/health` et les 3 appels `askJson`), `tests/llm.test.mjs`, `tests/fixtures/fake-claude.mjs` (nouveau). **Ne touche pas `extension/`.**

### 1. Couche fournisseur
- Déplacer le code pi actuel dans `server/src/llm/pi.js` (comportement inchangé).
- Créer `server/src/llm/claude.js` exposant le même contrat que `runPi` : `run(prompt, { cfg, task, schema, signal, timeoutSeconds }) → { text, data?, ms, runner, generation }`.
- `server/src/llm.js` devient une façade : `askJson(prompt, { cfg, task, schema, signal })` choisit le fournisseur selon `cfg.llm.provider`, garde `extractJson`, le second essai JSON, `cancelAll()` (remplace `cancelAllPi`, alias conservé) et `killTree`.
- `task` ∈ `letter | answers | tailor` ; il sélectionne modèle et effort.

### 2. Invocation de `claude` (vérifiée sur Claude Code 2.1.323)
```
claude -p --output-format json
       --model <cfg.llm.claude.model>          # claude-sonnet-5-5
       --effort <effort de la tâche>           # medium
       --tools ""                              # aucun outil
       --no-session-persistence
       --safe-mode --strict-mcp-config         # pas de CLAUDE.md, skills, hooks, MCP
       --system-prompt "<prompt système court et fixe>"
       [--json-schema '<schéma de la tâche>']
```
- Prompt envoyé sur **stdin**, `cwd` = `data/claude-workdir` (vide, créé au besoin).
- **Ne pas utiliser `--bare`** : il force `ANTHROPIC_API_KEY` et ignore la connexion OAuth/abonnement.
- `--system-prompt` remplace le long prompt système d'agent de code : moins de tokens, pas de comportement « coding agent ».
- Environnement : retirer les variables de la session parente (`CLAUDECODE`, `CLAUDE_CODE_ENTRYPOINT`, `CLAUDE_CODE_SESSION_*`, etc. — faire l'inventaire) comme `SESSION_ENV` pour pi. Documenter que si `ANTHROPIC_API_KEY` est défini, le CLI facture l'API au lieu de l'abonnement.
- Résolution du binaire sous Windows : `cfg.llm.claude.command` sinon recherche dans le PATH de `claude.exe` (installeur natif) puis `claude.cmd` (npm, `shell: true` dans ce seul cas). Même logique `resolve*` que pi.
- Schémas JSON : définir dans `server/src/llm/schemas.js` les schémas `letter`, `answers`, `tailor` à partir de ce que `index.js` / `cv-tailor.js` lisent déjà. Utiliser `structured_output` si présent, sinon `extractJson(result)`.
- **Avant d'écrire le parseur**, faire UN appel réel minimal (`echo 'Réponds {"ok":true}' | claude -p --output-format json --model claude-sonnet-5-5 --effort low --tools ""`) et figer la forme exacte de la sortie (`result`, `is_error`, `subtype`, `structured_output`, `modelUsage`, `total_cost_usd`, `duration_ms`…) dans la fixture. Ne rien supposer d'autre.
- Annulation / délai / limite de taille de flux : réutiliser exactement les mécanismes de `runPi` (`activeRuns`, `killTree`, timeout, plafond d'octets).
- `generation` (provenance) : `{ schema: 1, providerKind: 'claude-cli', requestedModel, requestedEffort, model (clé observée dans modelUsage), costUsd?, attempts }`. L'effort effectif n'est pas rapporté : le dire, comme pour pi. Ne jamais stocker de bloc de raisonnement.

### 3. Configuration
```yaml
llm:
  provider: claude            # claude | pi
  timeoutSeconds: 300
  claude:
    command: ""               # vide = PATH
    model: claude-sonnet-5-5
    effort: { letter: medium, answers: medium, tailor: medium }
  pi:                         # anciennes clés, migrées en lecture
    command: pi
    model: ""
    letterThinking: medium
    answersThinking: low
```
Rétrocompatibilité : un `config.yaml` existant avec `llm.command/model/letterThinking` sans `provider` doit continuer à fonctionner (lu comme `pi.*`). Décision : sans `provider` explicite → `claude` si le binaire est trouvé, sinon `pi`. Documenter.

### 4. `/health`
Ajouter `llm: { provider, available, version, model, effort: {...} }` (vérifié via `claude --version`, mis en cache 60 s). Remplacer `generation` par des réglages neutres vis-à-vis du fournisseur, en gardant les anciens champs pour l'extension 0.7.

### 5. Tests
- `tests/fixtures/fake-claude.mjs` : imite la sortie JSON enregistrée, modes `ok | invalid | retry | slow | error | child` (comme fake-pi), enregistre les flags reçus, n'émet jamais de raisonnement stocké.
- `tests/llm.test.mjs` : sélection du fournisseur, flags exacts (dont `--tools ""`, `--safe-mode`, pas de `--bare`), nettoyage d'environnement, annulation/kill de l'arbre, timeout, second essai, provenance, rétrocompat config.
- Les tests serveur/e2e existants restent sur `provider: pi` + fake-pi (configuration de test explicite) ; ajouter un passage `server.test` avec `provider: claude` + fake-claude.
- Critère de fin : `npm test` vert, plus un essai manuel réel de génération de lettre.

## Phase 2 — Refonte UI/UX · un seul agent (après fusion de 1A + 1B)

Un seul agent pour éviter les conflits dans `sidepanel.css` et `i18n.js`.

### Problèmes constatés (captures `docs/prototype/*.png`)
- Tout est visible en même temps : l'onglet Candidature empile Page + Candidature + Lettre (avec 2 blocs de provenance) + Remplissage, ~2 écrans de long.
- Avertissements longs répétés partout (« pi ne rapporte pas l'effort… », « ApplyPilot ne clique jamais… », comptes Workday…).
- Sélecteur de langue occupe une barre entière ; outils rares (diagnostic de formulaire) au même niveau que les actions principales.
- Le libellé « pi » est codé en dur (~20 chaînes).

### Nouvelle structure
1. **En-tête compact** : logo · version · pastille d'état (point coloré, détail au survol/clic). Langue, URL du serveur et réglages IA déplacés dans **Réglages** (icône ⚙).
2. **Onglets** : Accueil · Candidature · Recherche · Suivi. Profil et Réglages accessibles depuis ⚙ (Profil reste une vue complète).
3. **Candidature en étapes** (stepper vertical, une seule étape dépliée, les autres résumées en une ligne avec ✓) :
   1. *Offre* — titre, entreprise, checklist des exigences, « Analyser ».
   2. *Documents* — CV (sélection + inspecteur + CV sur mesure) et lettre.
   3. *Remplissage* — bouton principal, résultats groupés ; options dans un `<details>` « Options ».
   4. *Soumission* — « J'ai soumis ✓ », mémoriser les réponses.
4. **Barre d'action collante en bas** : l'action principale du contexte (Analyser / Générer la lettre / Remplir cette page / Arrêter). « Arrêter » y vit pendant un remplissage ou une recherche (supprime les deux boutons Stop de l'en-tête).
5. **Provenance IA en une ligne** : « Sonnet 5.5 · effort medium · 0,02 $ » ; détails (« effort effectif non rapporté… ») dans une infobulle ⓘ.
6. **Avertissements** : une phrase max visible ; texte complet derrière ⓘ ou montré une seule fois (préférence « vu » en `chrome.storage`). La règle « ne soumet jamais » reste visible près de *Soumission*.
7. **Accueil** : une carte « Contexte » (offre détectée → Analyser, formulaire → Remplir, candidature connue → Reprendre), compteurs, récents. Supprimer le paragraphe d'explication de la carte héro.
8. **Outils avancés** (diagnostic de formulaire, export CSV…) dans un menu « ⋯ ».
9. **Libellés neutres** : « l'IA » au lieu de « pi » ; le nom du fournisseur/modèle vient de `health.llm`.
10. **Réglages** : langue, URL serveur, fournisseur/modèle/effort en **lecture seule** depuis `/health` avec la marche à suivre pour modifier `config.yaml` (l'écriture du YAML depuis le panneau est reportée : elle perdrait les commentaires).

### Système visuel
- Tokens CSS sur `:root` (couleurs, rayons, espacements 4/8/12/16, typo 13/14/16), redéfinis sous `@media (prefers-color-scheme: dark)`.
- Composants uniformes : bouton (primary / secondary / ghost / danger), badge (ok/warn/bad/neutral), carte, ligne de résultat, état vide, squelette de chargement.
- Focus visible, contrastes AA, cibles ≥ 32 px, `aria-live` pour toasts et progrès.

### Contraintes
- Toute nouvelle chaîne : clé FR + EN dans `extension/i18n.js` ; `tests/i18n.test.mjs` étendu aux nouveaux modules de vues.
- Mettre à jour les e2e quand un sélecteur change (préférer garder `data-action` existants).
- Garder les comportements sensibles : confirmation avant d'écraser un brouillon, annulation, pas de reprise automatique.
- Critère de fin : `npm test` vert ; nouvelles captures `docs/prototype/*.png` (données fictives) en clair et sombre, FR et EN.
