# Plan 0.9.0 — Nouvelles offres, statistiques, usage IA, mémoire adaptée

Statut : **plan, non implémenté**. Rédigé le 2026-11-13. Exécution par des sous-agents Sonnet 5.5, sur la branche `feat/0.9.0`, livrée par PR.

Quatre fonctionnalités choisies :

| # | Fonctionnalité | Résumé |
|---|---|---|
| 4 | Nouvelles offres depuis la dernière visite | Marqueur « Nouvelle », compteur sur l'Accueil, relance de la dernière recherche en un clic. **Aucune collecte automatique.** |
| 5 | Statistiques du suivi | Entonnoir et taux de réponse par plateforme et par CV, avec la taille d'échantillon. |
| 7 | Usage et coût IA | Journal local de chaque génération, résumé par jour / tâche / modèle dans Réglages. |
| 9 | Mémoire de réponses adaptée | Une réponse mémorisée pour l'entreprise A est adaptée par Claude pour l'entreprise B, sans inventer de faits. |

Invariants (inchangés) : ApplyPilot ne clique jamais sur « Soumettre » ; serveur sur 127.0.0.1 ; aucun raisonnement interne stocké ; tout texte d'UI passe par `tr()` (clé FR + EN dans `extension/i18n.js`) ; commits à l'identité git de l'utilisateur, **sans trailer « Co-Authored-By » ni mention d'IA** ; jamais de push par les agents ; JS natif sans build.

---

## Décisions de conception

1. **Alertes = manuelles (4).** Pas de recherche en tâche de fond : Google peut bloquer, LinkedIn public est limité (429) et le README promet des actions explicites. À la place : le panneau sait ce qui est nouveau et propose « Relancer la dernière recherche ».
2. **Statistiques calculées côté serveur (5)**, fonction pure testable, aucun appel IA.
3. **Journal d'usage sans contenu (7)** : jamais de prompt, de réponse, de nom d'entreprise ni de donnée de profil.
4. **Mémoire adaptée seulement si l'IA est activée (9)** ; sinon comportement actuel, avec un avertissement orange. Une réponse adaptée demande toujours une relecture.

## Phase 1 — Serveur et script de contenu (3 agents en parallèle, worktrees)

### 1A — Usage IA (7) · fichiers : `server/src/llm.js`, `server/src/llm/*.js`, nouveau `server/src/usage.js`, `tests/usage.test.mjs`, `tests/llm.test.mjs`

- `server/src/usage.js` : `recordUsage(entry)` ajoute une ligne JSON à `data/usage/usage.jsonl` ; `usageSummary({ days })` agrège par jour, tâche et modèle ; `clearUsage()`. Rotation : conserver 180 jours et au plus 5 Mo.
- Entrée : `{ at, task, provider, model, effort, ms, attempts, costUsd, inputTokens, outputTokens, billing }`.
  - `billing` = `api` si `ANTHROPIC_API_KEY` est dans l'environnement, sinon `subscription`.
  - Tokens et coût : lire ce que le CLI renvoie déjà dans son JSON (`usage`, `modelUsage`, `total_cost_usd`). **Vérifier la forme réelle sur la fixture `fake-claude.mjs`** et ne rien supposer d'autre. pi : durée seulement.
- Point d'accroche unique dans la façade `askJson` (tâche, provider, génération), y compris les échecs (`ok: false`, sans message d'erreur détaillé).
- Routes (dans `index.js`, bloc dédié) : `GET /usage?days=30`, `DELETE /usage`. Réglage `usage.enabled` (défaut `true`) dans `config.js` / `config.example.yaml`.
- Tests : agrégation, rotation, désactivation, absence totale de contenu dans le fichier (canari dans le prompt), pas de crash si le fichier est corrompu.

### 1B — Statistiques (5) et nouveautés (4, serveur) · fichiers : nouveau `server/src/stats.js`, `server/src/search.js`, `server/src/store.js` (lecture seule), `extension/search/catalog.mjs`, tests

**Statistiques** — `GET /stats` :
- Entonnoir : offres identifiées (catalogue, type `job`) → candidatures créées → soumises → réponse (entrevue / offre / refus). Les statuts réels sont dans `store.js` ; l'agent lit les identifiants exacts avant de coder.
- Ventilation par **plateforme** (`catalogMeta` / `job.platform`) et par **CV** (`cvId`) : nombre de soumises, nombre de réponses, taux. **Si n < 5, renvoyer le taux comme `null`** et l'UI affiche « n = 3 » sans pourcentage. Délai médian soumission → première réponse si les dates existent.
- Fonction pure `computeStats(applications, catalogue)` ; aucun effet de bord.

**Nouveautés** — fichier séparé `data/search/meta.json` `{ lastRunAt, lastSeenAt, lastRun: { source, scope } }` (ne touche pas `discovery.json`, dont la validation est stricte) :
- `GET /search` renvoie `meta` ; `POST /search/seen` met `lastSeenAt` à maintenant ; chaque lot enregistré met `lastRunAt` et `lastRun`.
- « Nouvelle » = `status === 'new'` et `firstSeenAt > lastSeenAt`. Ajouter à `catalog.mjs` un filtre `since` pur et testé.
- Tests : n = 0, n < 5, plusieurs plateformes, candidature sans CV, méta absente, concurrence d'écriture (écriture atomique via `writeJson`).

### 1C — Mémoire adaptée (9) · fichiers : `server/src/store.js` (mémoire), `server/src/prompts.js`, `server/src/index.js` (`/answers` uniquement), `extension/content/mapping.js`, `extension/content/main.js`, fixtures de test

- `addToMemory` : marquer `adaptable: true` quand la valeur est un texte long (> 60 caractères), un champ `textarea`, ou contient `lastCompany` (insensible à la casse et aux accents).
- `memoryLookup` (content script) : pour une entrée `adaptable`, renvoyer le résultat avec `needsAdaptation: true` et `previous: { value, company }`, toujours **orange** avec la note « Réponse mémorisée pour {company} : relis-la ». La valeur reste remplie si l'IA est désactivée.
- Si l'IA est activée : ces champs partent dans `/answers` avec `previous` (champ `memoryAnswers` séparé de `memory`).
- `buildAnswersPrompt` : nouvelle section « Réponses mémorisées à adapter ». Règles : garder uniquement les faits présents dans le profil ou le CV ; remplacer toute mention de l'ancienne entreprise ou de l'ancien poste ; respecter la longueur maximale du champ ; ne rien inventer ; si la réponse ne s'applique plus, `value: null` avec une note.
- Réponse adaptée : confiance plafonnée à 0,8, note « Adaptée de {company} », toujours à relire.
- Tests : adaptation d'un texte contenant l'ancienne entreprise (fake provider), IA désactivée (valeur inchangée + avertissement), champ à choix (non adaptable, inchangé), absence d'invention (le prompt n'ajoute pas de faits hors profil).

Critère de fin de la phase 1 : `cd server && npm test` vert pour chaque agent. Ports de test fixes 4397/4398 : **ne pas lancer deux suites e2e en même temps** (voir 0.8.0).

## Phase 2 — Interface (1 agent, après fusion de la phase 1)

Un seul agent pour éviter les conflits dans `sidepanel.css`, `i18n.js` et `views/*`.

- **Accueil (4)** : compteur « {n} nouvelle(s) offre(s) depuis ta dernière visite » ; ligne « Dernière recherche : {date} · [Relancer] » qui relance `lastRun` (Google ou LinkedIn public, mêmes limites qu'aujourd'hui, **un clic = une exécution bornée**, jamais en arrière-plan).
- **Recherche (4)** : pastille « Nouvelle » sur les offres concernées, filtre « Nouvelles depuis ma dernière visite », `POST /search/seen` quand l'utilisateur ferme ou quitte l'onglet (pas à l'ouverture, pour ne pas effacer les pastilles avant lecture).
- **Suivi (5)** : sélecteur « Liste | Statistiques ». Statistiques = entonnoir en barres CSS, deux tableaux (plateforme, CV) avec « n = » et taux seulement si n ≥ 5, texte alternatif accessible, **pas de bibliothèque de graphiques**. Mention : « Petits échantillons : indicatif seulement ». Charger le skill `dataviz` avant d'écrire les barres.
- **Réglages (7)** : section « Usage IA » : aujourd'hui / 7 jours / 30 jours (générations, tokens, durée). Coût : « Coût facturé » si `billing: api`, sinon « Estimation (abonnement : rien n'est facturé à l'appel) ». Bouton « Effacer l'historique d'usage » avec confirmation. Interrupteur `usage.enabled` en lecture seule (modifiable dans `config.yaml`).
- **Remplissage (9)** : puces « à adapter » / « Adaptée de {company} » dans les résultats ; la liste de mémoire (Profil) affiche l'entreprise d'origine et le badge « adaptable ».
- Tests e2e : nouvelles offres (pastille, filtre, `seen`), relance bornée, statistiques avec n < 5, effacement de l'usage, puce « à adapter ». Étendre les scans de `tests/i18n.test.mjs`.
- Captures `docs/prototype/` régénérées (Accueil, Suivi/Statistiques, Réglages) avec données fictives.

## Risques

- **Forme du JSON du CLI** : si tokens/coût ne sont pas fournis comme prévu, 7 se limite à durée et compte de générations (dit explicitement dans l'UI).
- **Adaptation de mémoire** : risque d'invention de faits → prompt strict, relecture obligatoire, test de non-invention.
- **Statistiques** : échantillons très petits au début → taux masqués sous n = 5 ; aucune interprétation causale affichée.
